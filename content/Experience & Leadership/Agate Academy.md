> [!summary] TL;DR 
> > For five months, I participated in a program at Agate Academy, which is a government-sponsored program called [[MSIB]]. There, I served as a game programmer to develop a 3D game called Project Dilemma using [[Unity Engine]]. My primary focus was translating the [[Game Design Document]] (GDD) into functional code and building a scalable system architecture using the MVC pattern.
> > 
## Project Context
This training program ran from February through June 2024. The main challenge wasn’t just writing code, but simulating the actual workflow of a professional game studio. I had to collaborate directly within a cross-functional team made up of members from various departments. 
![[agate-team.webp | center]]

## Primary Responsibilities
As a Game Programmer, I am responsible for:
1. Serving as the technical bridge between the design vision (GDD) and implementation within the *engine*.
2. Ensuring that the code I write does not overlap with that of other team members and is easy to maintain.
3. Seamlessly integrating both 2D and 3D *gameplay* mechanics using assets produced by the *artist* team. 

## Technical Implementation
To achieve these goals, I took several technical steps:
* **Adoption of a Clean Architecture:** Instead of using conventional, messy *scripting* (spaghetti code), I implemented Agate’s built-in [[MVC Framework]] (Model-View-Controller). This allows the data logic (Model), user interface (View), and input flow (Controller) to be neatly separated.
* **Gameplay Mechanics**: Creating gameplay features and testing them before merging them with other programmers.
* **Asset Pipeline Integration:** Collaborating closely with *artists* to import and configure 2D and 3D assets directly into the Unity *scene* without breaking the hierarchy or compromising graphical optimizations.
* **Code Collaboration**: Using Git and GitHub to facilitate collaboration among programmers, thereby integrating existing code and features.
* **Debugging**: Reviewing features that have been developed to identify, fix, and eliminate errors in those features or in the code.
## Results
Our team successfully completed **Project Dilemma** and released a functional *gameplay* module on time. The use of MVC architecture proved to be crucial in preventing *conflicts* when *merging* code with other *programmers* in the repository.

## 💡 Reflections & Lessons
1. **Communication Is Key:** Writing good code is important, but being able to explain technical limitations to a *Game Designer* or request specific formats from a *2D/3D Artist* is far more important for a smooth production *pipeline*.
2. **Scalability from Day One:** Learning to use MVC made me realize that thinking about architecture early on will save dozens of hours of *debugging* later in the production phase.
